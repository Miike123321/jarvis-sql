# J.A.R.V.I.S. SQL Assistant

Локальный веб-чат с Gemini и PostgreSQL. Ассистент выполняет только read-only
запросы `SELECT`. Создание таблиц, представлений и индексов требует отдельного
подтверждения в интерфейсе.

## Настройка

Нужен Python 3.10+ и доступ к PostgreSQL. В корне проекта создайте виртуальное
окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Если файла `.env` ещё нет, скопируйте `.env.example` в `.env`. Заполните
`GEMINI_API_KEY`, `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. Не
перезаписывайте существующий `.env` образцом, если в нём уже есть нужные
значения. Файл `.env` исключён из Git.

Рекомендуется создать отдельного пользователя PostgreSQL с минимальными
разрешениями: доступом только к нужным схемам и таблицам для чтения, а также
только с теми правами `CREATE`, которые действительно нужны для подтверждаемых
операций.

## Запуск

Из этой папки выполните:

```bash
python -m uvicorn jarvis_backend:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Проверить настройки можно на
<http://127.0.0.1:8000/health>. `127.0.0.1` оставляет сервер доступным только
на этом компьютере.

## Ограничения

- Поддерживается PostgreSQL; тип базы выбран по основным настройкам исходного
  backend (порт 5432). Настройки подключения задаются только через `.env`.
- `SELECT` выполняется в read-only транзакции с тайм-аутом и лимитом результата.
- Интерфейс не может подменить SQL при подтверждении: сервер хранит запрос и
  выдаёт одноразовое подтверждение, действительное пять минут.
- Для подтверждения разрешены только одиночные `CREATE TABLE`, `CREATE VIEW` и
  `CREATE INDEX`; `DROP`, `ALTER`, `UPDATE`, `DELETE` и `INSERT` не выполняются.
