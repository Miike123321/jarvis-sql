# J.A.R.V.I.S. SQL Assistant

## Что это за проект

J.A.R.V.I.S. SQL Assistant — приложение на Python для работы с Microsoft SQL
Server через диалог с AI-моделью. Пользователь задаёт вопрос обычным языком,
ассистент формирует SQL-запрос, а приложение проверяет его и при разрешённом
типе запроса выполняет на настроенной базе. Результат возвращается в чат для
объяснения и дальнейших вопросов.

Проект предназначен для аналитиков, разработчиков и внутренних команд, которым
нужно быстрее исследовать данные и получать ответы из SQL Server без ручного
написания каждого запроса. Это интерфейс для запросов и анализа данных, а не
система администрирования или универсальная платформа для произвольных SQL-команд.

## Возможности

- Общение с данными на естественном языке с сохранением контекста диалога.
- Подключение к Gemini или к OpenAI-совместимому Omniroute.
- Подключение к Apache Superset через MCP-сервер с динамическим обнаружением
  доступных инструментов и их схем.
- Выполнение одного проверенного `SELECT` (включая read-only CTE) за вызов;
  ответы ограничены первыми 100 строками.
- Подготовка нескольких частей задачи в Streamlit и отправка их одним запросом.
- Семь управляемых SQL/Superset-сценариев в Streamlit: анализ данных и таблиц,
  поиск/просмотр Superset-объектов, добавление графика в выбранный дашборд и
  создание дашборда по шаблону.
- Предложение SQL для создания таблиц, представлений и индексов с отдельным
  просмотром и явным подтверждением пользователя перед выполнением.
- Настройка подключения к базе и ключа Gemini через боковую панель Streamlit
  либо через переменные окружения.

## Интерфейсы и компоненты

- **FastAPI и веб-чат** — backend с HTML-интерфейсом, WebSocket-чаты и endpoint
  `/health` для проверки состояния сервиса.
- **Streamlit** — альтернативный Python-интерфейс с боковой панелью настроек,
  проверкой подключения к базе и модели, а также черновиком составного запроса.
- **Конфигурация** — Microsoft SQL Server как источник данных; Gemini или
  Omniroute как провайдер AI-модели; необязательная интеграция с Superset через
  официальный MCP transport Streamable HTTP.

AI-модель не получает прямое подключение к БД: запросы к локальному SQL Server
выполняет backend через отдельный инструмент после проверки. Доступ к Superset
идёт только через MCP-клиент; Jarvis не подменяет MCP прямыми REST-вызовами.
Superset самостоятельно проверяет права пользователя. SQL-инструменты Jarvis
пропускают только одиночные read-only `SELECT`; постоянные объекты Superset
создаются только через инструменты, реально предоставленные MCP-сервером.

## Настройка

Нужен Python 3.10+ и доступ к Microsoft SQL Server. В корне проекта создайте виртуальное
окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

На каждом компьютере создайте локальный `.env` по образцу `.env.example` и
заполните `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, а также ключ
выбранного провайдера модели.
Не переносите секреты в репозиторий и не перезаписывайте существующий `.env`
образцом. Файлы с ключами и локальные настройки исключены из Git. Чтобы
подключиться с другого компьютера, ему также нужен сетевой доступ к выбранному
провайдеру модели и к указанному серверу SQL Server
(например, через корпоративную сеть или VPN).

Настройки БД можно задать в `.env` или сохранить через боковую панель
Streamlit. Ключ Gemini можно задать через `GEMINI_API_KEY` или ввести в
боковой панели Streamlit после выбора Gemini; введённый ключ сохраняется в
локальном файле `.jarvis_config.json`, который исключён из Git. При
необходимости задайте `GEMINI_MODEL`. Для Omniroute задайте
`OMNIROUTE_API_KEY` и, при необходимости, `OMNIROUTE_BASE_URL` (по умолчанию
используется `http://localhost:20128`).
Создайте отдельную учётную запись SQL Server с минимальными правами: только
нужные разрешения на чтение и, если требуется, разрешения на подтверждаемые
операции создания объектов.

## Интеграция с Apache Superset через MCP

### Prerequisites

- Экземпляр Superset с включённым и доступным пользователю MCP-сервисом.
- Клиент использует поддерживаемую Python SDK MCP ветку 1.x
  (`mcp>=1.30,<2`) и транспорт Streamable HTTP.
- MCP endpoint, предоставленный администратором Superset. Используется
  **Streamable HTTP**; Jarvis не запускает MCP-сервер и не поддерживает stdio
  для этой удалённой интеграции.
- Сетевой доступ Streamlit/FastAPI-приложения к этому endpoint. Для удалённых
  серверов требуется HTTPS.
- Если сервер требует Bearer-аутентификацию — выданный администратором
  Bearer-токен и соответствующие Superset-права. Оставьте токен пустым, только
  если endpoint доступен без дополнительного заголовка аутентификации.

Не подставляйте примерный URL: адрес и путь endpoint зависят от конфигурации
Superset и прокси. Запросите у администратора точный Streamable HTTP URL и
способ аутентификации. Поддерживается Bearer-токен в заголовке
`Authorization`; произвольные заголовки, OAuth login flow и stdio не
настраиваются в Jarvis.

### Конфигурирование и запуск

В `.env` задайте значения, выданные администратором:

```dotenv
SUPERSET_MCP_ENABLED=true
SUPERSET_MCP_URL=<точный Streamable HTTP endpoint от администратора>
SUPERSET_MCP_BEARER_TOKEN=<Bearer-токен, если он требуется>
```

Либо настройте интеграцию в боковой панели Streamlit: откройте
«Настройки конфигурации» → «Apache Superset MCP», укажите endpoint, включите
интеграцию и при необходимости введите Bearer-токен. Пустое поле токена
сохраняет ранее записанное значение; его можно удалить отдельным флажком.
После сохранения секрет не показывается повторно. Настройки из интерфейса
записываются в локальный `.jarvis_config.json` с правами `0600`; файл не
зашифрован, храните его в защищённом окружении и не публикуйте.
Для аварийного отключения интеграции независимо от сохранённых настроек
задайте `JARVIS_DISABLE_SUPERSET_MCP=true` в окружении процесса.

Для проверки нажмите «Проверить подключение к Superset MCP». Проверка
инициализирует MCP-сессию и читает `tools/list`, показывая число доступных
инструментов и отсутствующие возможности. Запустите приложение обычным
способом — например:

```bash
python -m streamlit run streamlit_app.py
```

Можно также задать указанные переменные в окружении процесса FastAPI перед
запуском через Uvicorn.

### Права Superset для MCP-пользователя

Попросите администратора Superset проверить и назначить перечисленные RBAC
права пользователю/роли, под которой MCP-сервер выполняет запросы:

```text
can_read on Chart
can_write on Chart
can_read on Dashboard
can_write on Dashboard
can_read on Dataset
can_write on Dataset
can_read on Database
can_read on SQLLab
can_execute_sql_query on SQLLab
can_estimate_query_cost on SQLLab
can_format_sql on SQLLab
can_write on SavedQuery
database_access
datasource_access
```

`an_read on Chart` из исходного списка интерпретировано как опечатка
`can_read on Chart`. Возможность назначить `can_format_sql` и
`can_estimate_query_cost` зависит от версии и настроек Superset. `database_access`
и `datasource_access` следует ограничить только нужными базами и источниками
данных. Права `can_write` расширяют возможности записи пользователя Superset;
выдавайте их только если действительно нужны постоянные изменения.

Этот список описывает **RBAC-права**, а не имена MCP-инструментов. Jarvis не
назначает права и не создаёт MCP tools из названий permissions. Реальные
инструменты и схемы по-прежнему берутся из `tools/list`; если сервер не
предоставляет нужную операцию, она останется недоступной даже при наличии
похожего RBAC-права. Проверки доступа Superset остаются обязательными.

### Поддерживаемые возможности и ограничения

Jarvis сверяет инструменты и JSON-схемы с текущим ответом MCP-сервера
`tools/list`; точные имена и параметры не зашиты вместо серверных метаданных.
В каталоге Jarvis поддержаны следующие группы инструментов, если сервер их
предоставляет:

- соединение и сведения об экземпляре: `health_check`, `get_instance_info`;
- базы, схемы и датасеты: `list_databases`, `get_database_info`, `get_schema`,
  `list_datasets`, `get_dataset_info`, `query_dataset`;
- графики: поиск и просмотр (`list_charts`, `get_chart_info`,
  `get_chart_data`, `get_chart_preview`, `get_chart_sql`), предварительные
  представления и создание/изменение (`get_chart_type_schema`,
  `generate_explore_link`, `generate_chart`, `update_chart`,
  `update_chart_preview`);
- дашборды: поиск и просмотр (`list_dashboards`, `get_dashboard_info`,
  `get_dashboard_data`), создание/изменение и добавление графика
  (`generate_dashboard`, `update_dashboard`,
  `add_chart_to_existing_dashboard`);
- SQL Lab: `execute_sql`, `open_sql_lab_with_context`, `save_sql_query`;
- virtual datasets: `create_virtual_dataset`.

Фактические возможности зависят от версии и настроек MCP-сервера и прав
пользователя. Недоступные инструменты не вызываются и не имитируются. Через
`execute_sql`, `save_sql_query` и `create_virtual_dataset` Jarvis пропускает
только одиночный read-only `SELECT` (включая CTE); не-`SELECT`, DDL и пачки
команд отклоняются до MCP-вызова. Это не отменяет проверок доступа Superset.
Текстовые ответы и URL previews передаются модели; image-only содержимое
preview не отображается в текущем текстовом интерфейсе.

Просмотр и предварительный просмотр не равны сохранению: `generate_chart` по
умолчанию создаёт preview, а сохранение графика, создание virtual dataset,
сохранение SQL, создание/изменение дашборда и постоянное изменение графика
требуют явной просьбы пользователя и соответствующих прав Superset. Для
добавления графика в существующий дашборд используется
`add_chart_to_existing_dashboard`, а не создание нового дашборда. Jarvis
возвращает только URL, полученный в ответе инструмента, и не строит ссылки
самостоятельно.

### Управляемые сценарии и контроль расходов

В Streamlit доступны семь коротких сценариев:

1. Ответ на вопрос по SQL-данным.
2. Просмотр структуры SQL-таблицы.
3. Сравнение показателей SQL.
4. Поиск баз, датасетов, графиков и дашбордов Superset.
5. Просмотр выбранного графика, дашборда или датасета.
6. Добавление выбранного графика в существующий дашборд — оба объекта
   выбираются из загруженных списков; перед запуском требуется подтверждение.
7. Создание одного дашборда по шаблону содержания: руководительские KPI,
   продажи, финансы, операции или клиенты. Это шаблоны назначения и содержания,
   а не обещание конкретной цветовой темы; перед запуском требуется
   подтверждение.

Каждый сценарий создаёт отдельный короткий контекст, получает только нужные
инструменты и имеет свой небольшой лимит вызовов. В свободном Streamlit-чате
сохраняется обычный текстовый ввод, но инструменты Superset для постоянного
создания, сохранения и изменения объектов там отключены. Для таких операций
используйте подтверждённые сценарии. Ограничения проверяются и на стороне
Jarvis, а не только в тексте промпта; один сценарий может выполнить не более
одного постоянного изменения.

Для снижения расходов каждый ответ модели ограничен: Gemini — 2048, Omniroute —
1200 выходными токенами. Если Gemini всё же исчерпал лимит, приложение покажет
частичный текст с предупреждением либо предложит попросить более краткий ответ;
автоматического повторного платного запроса нет.
Gemini может сделать максимум 4 вызова инструментов за сообщение; Omniroute —
максимум 3 раунда и 4 вызова. В контекст свободного чата сохраняются последние
6 пользовательских ходов, результаты Superset для модели ограничены 12 000
символами на инструментальный вызов. Это ограничивает объём запросов, но не
является гарантией фиксированной суммы: стоимость зависит от выбранной модели,
её тарифов, размера входных данных и числа вызовов. Для предсказуемого бюджета
проверяйте тарифы провайдера и его usage/billing панель.

### Troubleshooting

- **Нет соединения / timeout:** проверьте точный URL и путь MCP endpoint,
  сетевую доступность и то, что Superset MCP-сервис включён. Jarvis не
  угадывает URL или транспорт.
- **HTTP 401/403:** проверьте выданный Bearer-токен, срок его действия и
  разрешения пользователя Superset. Jarvis не повышает права и не обходит
  read-only доступ.
- **Инструмент отсутствует:** он не включён сервером, не поддерживается его
  версией или скрыт от текущего пользователя. Сверьте права и настройки
  Superset MCP; интерфейс покажет отсутствующие инструменты.
- **SQL отклонён:** разрешён только один read-only `SELECT`. Для другого
  действия используйте штатный интерфейс Superset с нужными правами.
- **HTTP endpoint доступен, но MCP-ответ ошибочный:** передайте администратору
  Superset диагностический текст без секретов; не добавляйте токен или пароль
  в URL.

## Запуск

Из этой папки выполните:

```bash
python -m uvicorn jarvis_backend:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Проверить настройки можно на
<http://127.0.0.1:8000/health>. `127.0.0.1` оставляет сервер доступным только
на этом компьютере.

## Альтернатива: Streamlit

Streamlit использует те же `.env` и настройки Gemini/Omniroute, но предоставляет
отдельный Python-интерфейс. В нём можно добавлять задачу несколькими частями и
отправлять их ассистенту одним нажатием:

```bash
python -m streamlit run streamlit_app.py
```

Откройте <http://localhost:8501>. На Windows активируйте окружение командой
`.venv\Scripts\activate` вместо `source .venv/bin/activate`.

## Ограничения

- Поддерживается Microsoft SQL Server (порт по умолчанию 1433).
- Для чтения допускается один `SELECT` (включая CTE), без команд записи и
  `SELECT INTO`; результат ограничен 100 строками.
- Лимиты AI-вызовов и размер результата Superset описаны в разделе
  «Управляемые сценарии и контроль расходов»; это ограничения объёма, а не
  точный денежный потолок.
- Интерфейс не может подменить SQL при подтверждении: сервер хранит запрос и
  выдаёт одноразовое подтверждение, действительное пять минут.
- Для подтверждения разрешены только одиночные `CREATE TABLE`, `CREATE VIEW` и
  `CREATE INDEX`; `DROP`, `ALTER`, `UPDATE`, `DELETE` и `INSERT` не выполняются.
- Локальный файл настроек содержит ключи доступа. Не публикуйте его, ограничьте
  права учётной записи БД и замените ключи, если они попали в общий доступ.
